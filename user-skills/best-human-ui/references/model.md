# モデルの原則

収録日: 2026-07-16

情報や機能を、利用者が認識する対象とその関係として組み立てるための原則。設計対象に応じて必要な項目だけを参照する。

## 3. メンタルモデル

- 公式タグ: `shig-clarity`
- 使う場面: 新しい概念、機能、操作体系を利用者へ伝えるとき。
- 判断: 構成と振る舞いを、利用者が既に知る慣用表現や比喩から予測できるようにする。内部実装の都合より、利用者が抱く仕組みのイメージを優先する。
- 確認: 初見の利用者は、既知の経験から次の操作と結果を予測できるか。
- 出典: https://www.sociomedia.co.jp/9012

## 23. オブジェクトベースにする

- 公式タグ: `shig-object-orientation`
- 使う場面: 要件から情報構造、画面構成、主要な操作を設計するとき。
- 判断: 要求された手順を画面として並べず、利用者が関心を向ける対象を抽出する。対象の一覧や詳細を起点に、その対象へ操作を適用できる構成にする。
- 確認: UIの中心に、利用者が見つけ、選び、操作する具体的な対象が現れているか。
- 出典: https://www.sociomedia.co.jp/9240

## 24. ビューはオブジェクトを表象する

- 公式タグ: `shig-object-orientation`
- 使う場面: 一覧、詳細、カード、アイコンなど、同じ情報の表示方法を設計するとき。
- 判断: 各ビューがどの対象を表すかを明確にし、ひとつの対象に必要な複数の表現を用意する。それらの組み合わせから、利用者がシステム全体を理解できるようにする。
- 確認: 各表示要素が表す対象を特定でき、同じ対象の別ビューとの関係も理解できるか。
- 出典: https://www.sociomedia.co.jp/9256

## 33. ナビゲーション項目は名詞にする

- 公式タグ: `shig-navigation`, `shig-object-orientation`
- 使う場面: グローバルナビゲーション、サイドバー、業務メニューを設計するとき。
- 判断: ナビゲーションは「登録する」「確認する」などの作業ではなく、情報や対象の種類を示す具体的な名詞で構成する。同じ対象の一覧が作業別に分散する設計を避ける。
- 確認: 項目名から、その先に何があるかを具体的に想像できるか。
- 出典: https://www.sociomedia.co.jp/9323

## 34. アイコンは名詞または形容詞を表す

- 公式タグ: `shig-clarity`, `shig-object-orientation`
- 使う場面: ツールバー、状態表示、操作ボタンへアイコンを割り当てるとき。
- 判断: アイコンには対象そのもの、または操作後に得られる状態を表すモチーフを使う。一般に定着していない処理を絵だけで伝えず、必要なテキストラベルを付ける。
- 確認: アイコンは対象または結果の状態を示しており、記号の意味を暗記しなくても判断できるか。
- 出典: https://www.sociomedia.co.jp/9330

## 35. データをバインドする

- 公式タグ: `shig-consistency`, `shig-object-orientation`
- 使う場面: 同じデータを一覧、詳細、編集フォームなどへ同時に表示するとき。
- 判断: 同一対象を表す複数のビューをひとつのモデルに結び付け、変更を双方向かつ即時に同期する。保存や再読込といった内部処理を利用者に管理させない。
- 確認: ひとつのビューで変更した内容が、同じ対象を示すすべてのビューへ直ちに反映されるか。
- 出典: https://www.sociomedia.co.jp/9340

## 38. ユーザーが入力したものはユーザーのもの

- 公式タグ: `shig-form`
- 使う場面: 入力フォーム、設定、投稿、作成した項目の保存と編集を設計するとき。
- 判断: 利用者が入力または設定した内容は原則として保持し、後から変更できるようにする。利用者が追加した項目には削除手段も用意する。
- 確認: 利用者は自分が入力、設定、追加した内容を保存、変更、削除できるか。
- 出典: https://www.sociomedia.co.jp/9398

## 87. ユーザーの道具にする

- 公式タグ: `shig-controllability`
- 使う場面: 事業要件、販売要件、通知や同意の初期値を製品体験へ反映するとき。
- 判断: システムを提供者が利用者へ行動を強いる手段ではなく、利用者自身の目的を達成する道具として設計する。例えばECでは、売る側の都合より買う側の行為を起点に判断する。
- 確認: 初期値や導線は提供者の都合を押し付けず、利用者が自分の意思で目的を達成できるものか。
- 出典: https://www.sociomedia.co.jp/9824

## 98. ユーザーイリュージョンをもたらす

- 公式タグ: `shig-speculative`
- 使う場面: 製品の世界観、直接操作、処理時間や容量の見せ方を設計するとき。
- 判断: 内部の計算量やデータ処理をそのまま露出せず、利用者が対象へ直接働きかけられる一貫した仮想世界を作る。技術上の処理差が体験上の制約にならないなら、利用者にとって自然な並びと振る舞いを選ぶ。
- 確認: 利用者は内部処理を意識せず、画面上の対象とその世界に集中できるか。
- 出典: https://www.sociomedia.co.jp/9916

## 99. デザインは新しい意味を提案する

- 公式タグ: `shig-speculative`
- 使う場面: 新製品や新機能のコンセプトを定め、既存の解決策を越える価値を検討するとき。
- 判断: 調査結果から既知の問題を解くだけで終わらず、製品や行為を捉える新しい意味を提案する。外部の事実を踏まえたうえで、どの体験を実現するかを設計者が明確に定める。
- 確認: このデザインは既存手段の改善だけでなく、利用者へ新しい行為や物事の見方を提示しているか。
- 出典: https://www.sociomedia.co.jp/9928

## 100. 人類にポジティブな影響を与える

- 公式タグ: `shig-speculative`
- 使う場面: 製品の長期的な価値、社会的影響、設計原則を評価するとき。
- 判断: 目先の目的達成だけでなく、人の弱さを補い、能力や生活の豊かさを高める道具を目指す。道具に蓄積された文化や知恵を尊重し、将来へ渡す影響まで考える。
- 確認: このデザインは人の能力と生活を長期的に豊かにし、文化として残す価値があるか。
- 出典: https://www.sociomedia.co.jp/9940
