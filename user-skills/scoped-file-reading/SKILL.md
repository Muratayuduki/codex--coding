# 必要なファイルだけを読む

調査を始める前に、次の四点を依頼と既知の情報から短く定める。不明点のうち仕様や安全性を左右するものだけ確認する。

- **What**: 変更または確認する振る舞いと、対象外の作業。
- **Where**: 手掛かりとなる機能名、パス、エラー、コマンド、関連文書。
- **Boundary**: 変更してよい場所、外部接続やデータ変更の可否、既存の承認。
- **Done**: 観測できる完了条件と、実行する最小の検証。

## 参照基準

まず指定されたパスと、その親階層に適用される `AGENTS.md` などの指示を確認する。次にファイル名やシンボルを検索し、候補のパスだけを列挙する。内容は下表の条件に当てはまるファイルから必要な箇所だけ読む。

| ファイル | 読む条件 | 最初に読む範囲 |
| --- | --- | --- |
| `AGENTS.md` と同等の指示 | 対象パスに適用される場合 | 該当する指示全体 |
| `README.md`、設計文書 | 起動方法、境界、仕様がコードから判断できない場合 | 該当見出しと周辺 |
| マニフェスト、設定 | 実行方法、依存関係、設定値が判断に必要な場合 | 関連キーとスクリプト |
| 実装ファイル | 対象の振る舞いを定義または呼び出す場合 | 該当シンボルと直接の呼び出し元・先 |
| テスト、fixture | 既存の期待値または検証方法を知る場合 | 対応するケースと準備部分 |
| ログ、生成物 | 再現や出力の比較に必要な場合 | 該当箇所。機密情報を出力しない |
| スキルの `references/` | `SKILL.md` が現在の作業に対応する条件を示す場合 | 対応する参照ファイルだけ |
| スキルの `scripts/`、`assets/` | 実行、修正、成果物への組み込みが必要な場合 | 対象ファイルだけ。実行のみなら中身は読まなくてもよい |

検索は `rg --files` や `rg -n` で候補を絞る。ファイル名、シンボル、エラー文など、得られた手掛かりから始める。候補が多い場合は対象ディレクトリと拡張子を限定する。関連のないファイルを一括で開かない。

## 範囲を広げる条件

読んだ箇所だけでは依存関係、公開契約、失敗原因、テストの期待値を確定できないときに限り、直接つながるファイルへ一段ずつ広げる。各段階で「何を判断するために読むか」を明確にする。検索結果だけで十分ならファイル本文は開かない。推測と確認済みの事実を区別する。

実装後は変更箇所と対応するテストを確認する。失敗が変更に起因する場合は修正して影響するテストを再実行する。テスト用データには使い捨ての fixture を使い、Boundary で許可されていない本番環境や外部サービスには接続しない。
